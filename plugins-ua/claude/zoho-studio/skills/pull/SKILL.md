# Pull

Оновлює завантажені файли проєкту zoho-studio і каже людині, що змінилось в організації, у звіті, що лежить поруч із кодом. Які pull є і як читати завантажені файли — бери з `zoho-studio instructions` (`zoho-studio instructions z-crm` для читання); порядок роботи в проєкті — у `/zoho-studio:basics`.

## Goal

Завантажені файли актуальні, а звіт у `changes/zoho-crm/` називає кожну зміну, яку приніс pull, — або людина почула, що нічого не змінилось.

## Workflow

1. **Перевір git.** Звіт будується з git, тож проєкт має бути репозиторієм хоча б з одним комітом. Не є — запропонуй `git init` і перший коміт проєкту як він є; без цього зупинись.
2. **Перевір, що завантажені файли закомічені.** `git status --porcelain -- data/` показує незакомічені зміни в завантажених файлах. Якщо вони є, скажи про це і спитай: спершу закомітити їх чи продовжити, і тоді вони змішаються з цим звітом. Зміни поза `data/` тут не важать.
3. **Спитай, що тягнути**, якщо людина ще не сказала («поля Leads»). За замовчуванням запропонуй пресет: `zoho-studio preset` перелічує пресети проєкту, а вбудований тягне весь CRM. Людина може обрати інший пресет чи одну частину; окремі pull — у `zoho-studio instructions z-crm`.
4. **Зроби pull.** Запусти обраний пресет чи команду. Код виходу 1 означає, що деякі елементи не завантажились: продовжуй звіт і перелічи збої в ньому. Збережи рядок `Moved N removed files to data/.removed/<date-time>/`, якщо pull його надрукував.
5. **Знайди, що змінилось.** `git status --porcelain -- data/` — додані, змінені й видалені файли, `git diff -- data/` — що змінилось усередині. Видалений файл pull переніс у папку, яку називає той рядок. Нічого не змінилось — скажи людині, що змін немає, і зупинись: без звіту.
6. **Напиши звіт** `changes/zoho-crm/<YYYY-MM-DD-HHMM>-pull.md`, за місцевим часом, мовою, якою говориш з людиною:
   - підсумок у два-три речення: що завантажено і головні зміни;
   - **Додано**, **Змінено**, **Видалено** — по сутностях (модуль, поле, функція, правило workflow…), кожна з тим, що це означає: нове поле і його тип, змінена умова правила, правка в коді функції, видалений вебхук із шляхом до його файлу в `data/.removed/`;
   - **Не завантажено** — елементи, що не вдались, з причиною, яку дав pull.

   Без сирого diff: його зберігає git.
7. **Запропонуй коміт** `data/` і звіту разом, з повідомленням на зразок `chore(data): pull zoho-crm, <головні зміни>`. Коміть лише тоді, коли людина скаже.

## Rules

- Перш ніж назвати зміну, прочитай її з файлів: тип поля, умову правила, код функції — не лише з назви файла.
- Описуй, що змінилось в організації, а не у файлах: «у списку Stage з'явилось значення Lost», а не «змінився Stage.json».
- Залишай `data/` таким, як його записав pull: звіт описує його і нічого в ньому не змінює.

## Output

- Шлях до звіту або «змін немає».
- Елементи, що не завантажились, якщо такі є.
- Запропонований коміт, що чекає слова людини.
