# Sources

Zoho CRM змінюється, і пам'ять про нього часто хибна чи застаріла. Цей скіл дає кілька базових фактів по кожній темі, щоб агент поставив правильне питання, і каже, де знайти відповідь. Документацію він не повторює: подробиці читай у джерелі. Що вміє CLI zoho-studio — у `zoho-studio instructions`; порядок роботи в проєкті — у `/zoho-studio:basics`.

## Goal

Кожен факт про Zoho, на який спирається відповідь чи код, узято з джерела, прочитаного в цій сесії, і людина бачить, з якого.

## How to look things up

Користуйся джерелами в такому порядку і зупиняйся на першому, що відповідає:

1. **`zoho-studio instructions`** — коли тема торкається CLI (`… z-crm:functions`, `… z-crm:widgets`, `… z-crm`). Там же описано, як Zoho поводиться насправді там, де це розходиться з документацією, за спостереженнями в реальних організаціях; це важливіше за решту джерел.
2. **context7** — коли його інструменти доступні. Став конкретне питання; відповідь цитує сторінки Zoho з їхніми URL. Бібліотеки: Deluge `/websites/zoho_deluge_help`, REST API v8 і COQL `/websites/zoho_crm_developer_api_v8`, Client Script `/websites/zohocrm_dev_explore_client-script`, віджети `/websites/zohocrm_dev_explore_widgets_v1_5`, решта документації для розробників `/websites/zoho_crm_developer`.
3. **OpenAPI-специфікація Zoho CRM**, яку ставить `/zoho-studio:setup` (де вона лежить — у `${CLAUDE_PLUGIN_ROOT}/references/dependencies.md`). У `v8.0/` по папці на ресурс (`record`, `coql`, `functions`, `modules`, `fields`, `layouts`, `org`, …). Прочитай `<resource>/index.md`, щоб вибрати операцію, потім `operations/<operationId>/operation.md` — параметри, тіло й помилки, і `examples/` — справжні відповіді з помилками. Скоупи OAuth — у `security` операції в `<resource>.yaml`. Шукай через `grep`; не читай `.yaml` цілком — файли великі.
4. **Документація Zoho** — лише коли context7 недоступний: починай з https://www.zoho.com/crm/developer/docs/ (REST API, COQL, Client Script, віджети, функції) або https://www.zoho.com/deluge/help/ (Deluge). Сторінки на `developer.zoho.com/crm/explore/` рендеряться лише в браузері й без нього приходять порожніми.

Коли джерела розходяться, скажи про це людині й орієнтуйся на `instructions`, потім на специфікацію, потім на документацію. Коли організація поводиться не так, як каже будь-яке джерело, скажи людині, що було надіслано і що відповів Zoho: таке спостереження важить більше за будь-яку сторінку.

## Topics

### Deluge functions

- Deluge виконується на серверах Zoho. Функція CRM має категорію, яка визначає тип повернення і де її можна викликати; оголошення, категорії і те, як Zoho поводиться з кодом, — у `zoho-studio instructions z-crm:functions`.
- HTTP-виклики йдуть через `invokeurl` з іменованим connection; значення `connection:` — рядковий літерал, а не змінна. Connections налаштовуються в інтерфейсі Zoho.
- Записи читаються й пишуться задачами `zoho.crm.*`; запис через API запускає правила workflow, лише коли сам їх просить (`trigger`).
- Джерела: context7 Deluge — вбудовані функції й задачі `zoho.crm.*`. Щоб спробувати код, `z-crm:functions:run` виконує його в організації по-справжньому.

### REST API

- Базова адреса `https://www.zohoapis.<dc>/crm/v8/`, заголовок `Authorization: Zoho-oauthtoken <token>`; модулі й поля — за API-назвами, а не мітками.
- Кожна операція потребує скоупів, перелічених у специфікації; без потрібного відповідає `OAUTH_SCOPE_MISMATCH`.
- Списки посторінкові, а запис приймає обмежену кількість записів за виклик; ліміти — у `record/index.md` специфікації.
- Джерела: специфікація — endpoints, параметри, ліміти й помилки; context7 API v8 — поняття й посібники. Власні модулі й поля організації вже завантажені: читай їх із проєкту, як описує `zoho-studio instructions z-crm`.

### Client Script

- JavaScript на сторінці CRM у браузері через API ZDK — не Deluge; DOM сторінки, `window` і `fetch` йому недоступні.
- Скрипт прив'язаний до модуля, layout, сторінки й події; на іншому layout чи сторінці він мовчки не спрацьовує. CLI скрипти лише завантажує; змінюють їх в інтерфейсі Zoho.
- Джерела: context7 Client Script — API ZDK і які події є на яких сторінках. У специфікації Client Script немає; вона покриває лише REST-виклики, які робить скрипт.

### Widgets

- HTML і JavaScript в iframe всередині CRM, що спілкуються з ним через JS SDK (`ZOHO.embeddedApp`, `ZOHO.CRM.*`). Обробники, зареєстровані після `ZOHO.embeddedApp.init()`, ніколи не спрацьовують.
- Збираються й пакуються CLI Zoho `zet`; хостяться в Zoho або за зовнішньою HTTPS-адресою.
- Джерела: context7 віджети v1.5 — SDK і `zet`. Локальне тестування віджета і методи SDK з їхніми відповідями — `zoho-studio instructions z-crm:widgets` і `… z-crm:widgets:serve`.

### COQL

- Мова запитів лише на SELECT по записах CRM: `POST /crm/v8/coql` з `{"select_query": "…"}`, що потребує `ZohoCRM.coql.READ` разом із доступом на читання модуля.
- Лише API-назви полів і модулів; `LIMIT offset, count` — зсув іде першим; три й більше умов у WHERE потребують дужок, як `((A and B) and C)`.
- Джерела: context7 API v8 — синтаксис, join і ліміти; відповіді з помилками — `coql/operations/executeCOQLQuery/examples/` у специфікації. Тип поля, від якого залежить, як його фільтрувати, — у завантажених полях проєкту.

## Rules

- Називай джерело факту про Zoho, на який спираєшся, — текст `instructions`, відповідь context7 з її URL чи файл специфікації, — щоб людина могла перевірити.
- Надавай перевагу цілеспрямованому пошуку перед читанням цілого документа: джерела великі, і читання цілком марнує контекст сесії.
- Твердження з пам'яті, форуму чи нотаток іншої команди вважай здогадом, який треба перевірити, а не фактом.

## Output
