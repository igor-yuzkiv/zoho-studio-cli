# Залежності плагіна zoho-studio

Що плагіну і CLI zoho-studio потрібно на машині: як перевірити кожну залежність, як її встановити чи оновити і що сказати людині. `/zoho-studio:setup` починає з клону, потім проходить залежності по порядку. Нова залежність додається сюди, а не в скіл.

Кожне встановлення чи оновлення виконується лише після згоди людини саме на цю дію.

## Клон zoho-studio: де він і чи актуальний

- **Знайти:** у `claude plugin marketplace list --json` є запис з `"name": "zoho-studio"` і `"source": "directory"`; його `path` — це клон. Переконайся, що там лежить `package.json` з `"name": "zoho-studio-cli"`.
- **Немає:** плагін встановлено з git-URL, а не з папки, тож клону, з якого збирати CLI, немає. Спитай у людини шлях до її клону або запропонуй клонувати репозиторій туди, куди вона скаже, і додати цю папку як маркетплейс (`claude plugin marketplace add <path>`).
- **Чи актуальний:** `git -C <clone> fetch --quiet`, потім `git -C <clone> status -sb`: «behind N» означає, що є новіші коміти. Версія, яка зараз використовується, — `version` у `<clone>/package.json` (те саме число в `plugin.json` плагіна).
- **Оновлення:** `git -C <clone> pull --ff-only`. Не підтягуй зміни, коли в клоні є локальні зміни (`git -C <clone> status --porcelain` не порожній) або він на гілці, відмінній від `master`: скажи людині й пропусти — це її зміни.
- **Після оновлення:** скіли щойно змінилися під запущеною сесією. Скажи людині перезапустити сесію (або виконати `/reload-plugins`) і запустити `/zoho-studio:setup` знову, після чого зупинись.

## Залежності

### Bun

- **Потрібен для:** CLI (його збирають і запускають через Bun) і скриптів проєктів.
- **Перевірка:** `bun --version` друкує 1.3 або новішу.
- **Встановлення чи оновлення:** `curl -fsSL https://bun.sh/install | bash`. Скрипт ставить Bun у `~/.bun/bin` і додає цю папку в профіль оболонки, тож поточна оболонка може ще не бачити `bun`: виконуй наступні кроки через `~/.bun/bin/bun` і скажи людині відкрити новий термінал.

### CLI zoho-studio

- **Перевірка:** `zoho-studio --version` дорівнює `version` у `<clone>/package.json`. Якщо оболонка не знаходить `zoho-studio`, перевір `~/.local/bin/zoho-studio` — CLI може бути встановлений, але не в `PATH`.
- **Встановлення чи оновлення:** `bun run setup` у клоні (`cd <clone> && bun run setup`). Він збирає CLI, створює посилання `~/.local/bin/zoho-studio` і реєструє пакети для скриптів проєктів.
  - Він зупиняється, коли `~/.local/bin/zoho-studio` — щось інше: посилання на інший клон або файл, — і каже, що там лежить. Покажи це людині; перезапускай з `--force` лише з її згоди.
  - Коли `~/.local/bin` немає в `PATH`, він друкує рядок, який треба додати для оболонки людини. Передай цей рядок; не змінюй її файли оболонки.

### crm-oas — OpenAPI-специфікація Zoho CRM

- **Потрібна для:** скілів, що шукають відомості про REST API Zoho CRM у першоджерелі, а не з пам'яті.
- **Де:** `~/.zoho-studio/references/crm-oas` — git-клон https://github.com/zoho/crm-oas.
- **Перевірка:** папка існує і є git-репозиторієм (`git -C ~/.zoho-studio/references/crm-oas rev-parse`); потім `fetch --quiet` і `status -sb` показують, чи вона відстає.
- **Встановлення:** `git clone https://github.com/zoho/crm-oas ~/.zoho-studio/references/crm-oas` (за потреби створює `~/.zoho-studio/references/`).
- **Оновлення:** `git -C ~/.zoho-studio/references/crm-oas pull --ff-only`.
- **Не git-репозиторій:** у папці лежить щось інше — скажи людині й залиш як є.

### context7 — MCP-сервер документації (необов'язковий)

- **Потрібен:** скілу `sources`, щоб шукати в документації Zoho з цитатами й посиланнями.
- **Перевірка:** `claude mcp get context7` знаходить сервер, або його інструменти доступні в сесії.
- **Встановлення:** `claude mcp add --scope user context7 -- npx -y @upstash/context7-mcp` (потрібен Node.js з `npx`). Діє з наступної сесії.
- **Без нього:** `sources` переходить на документацію Zoho в мережі; більше ніщо від нього не залежить.

### zet — CLI віджетів Zoho (необов'язковий)

- **Потрібен:** скілу `widget-add`, щоб створити віджет на чистому HTML (`zet init`) і запакувати та перевірити віджет для Zoho (`zet pack`, `zet validate`). Тестування віджетів в емуляторі без нього працює.
- **Перевірка:** `zet --version` друкує версію.
- **Встановлення:** `npm install -g zoho-extension-toolkit` (потрібен Node.js з `npm`). Якщо немає дозволу писати в глобальну папку npm, скажи людині, а не використовуй `sudo`.
- **Без нього:** віджети так само запускаються й тестуються локально; лише пакування для Zoho лишається за людиною.

### Playwright — у проєкті, для тестів віджетів

- **Потрібен:** скілу `widget-testing`; тести працюють у Node.js, а не в Bun, тож Node.js має бути встановлений.
- **Перевірка:** `@playwright/test` є в `package.json` проєкту, і `bunx playwright --version` друкує версію; `node --version` — для Node.js.
- **Встановлення:** у проєкті `bun add -d @playwright/test`, потім `bunx playwright install chromium` (завантажує браузер). Node.js — з nodejs.org або через менеджер версій людини (`nvm`); спитай людину, це її машина.
- **Без нього:** емулятор так само запускає віджети вручну (`z-crm:widgets:serve`, `zoho-studio browser`); бракує лише автоматичних тестів.
