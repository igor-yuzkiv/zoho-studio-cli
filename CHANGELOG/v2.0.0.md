# zoho-studio v2.0.0 — 2026-11-28

## Summary

This version brings the zoho-studio Claude Code plugin: skills that set up the machine, pull with a report of changes, look up Zoho facts, write scripts, and add and test widgets. Project scripts now only read from Zoho unless they turn writes on, and a widget's code and tests live in one folder with the emulator starting the widget itself. It is a major version because the widget folder layout changed and scripts that write need one new line: see How to update.

## Changes

### Added

- The Claude Code plugin `zoho-studio`, installed from the same clone as the CLI and of the same version, with the skills:
  - `setup` — checks and installs what the CLI and the plugin need, each step only with your agreement;
  - `basics` — how an agent works in a zoho-studio project;
  - `pull` — pulls and writes a readable report of what changed in the organization into `changes/zoho-crm/`;
  - `sources` — where to look up Deluge, the REST API, COQL, Client Script and widgets instead of answering from memory;
  - `scripts` — solves what the CLI has no command for with a script on the packages;
  - `widget-testing` — tests a widget with scenarios, mocks and Playwright, with screenshots;
  - `widget-add` — registers an existing widget or creates a new one on Vue, React or plain HTML that runs in the emulator and packs with Zoho's `zet`.
- `allowCrmWrites()` in `@zoho-studio/zoho-crm`, and a `README.md` in each package that maps its API for scripts.
- Widgets: `run` in `widget.json` — the command that starts the widget. The emulator starts it at the widget's first session when nothing answers at its `url`, and stops it when the emulator stops. `z-crm:widgets:make --run=<command>` writes it.
- Widgets: mocks in their own files, `testing/mocks/<name>.ts` with `defineWidgetMocks`, picked by scenarios and tests with `use: [...]`.
- `zoho-studio init` adds `.claude/settings.json`: Claude Code runs `zoho-studio instructions` without asking, asks before running a project script or `bun run migrate`, and its file tools do not read `.env` files or the credentials in `~/.zoho-studio`.
- `z-crm:status` prints the organization's type, domain and data center.

### Changed

- **Project scripts read by default.** The CRM client refuses any request that can change the organization — every `POST`, `PUT`, `PATCH` and `DELETE` except `POST /coql` — with `CRM_WRITES_DISABLED`, and sends nothing, until the script calls `allowCrmWrites()`. The CLI's commands and `bun run migrate` turn writes on for themselves.
- **The widget folder layout.** `widgets/<name>/` holds `widget.json`, the widget's code in `src/`, and `testing/scenarios/`, `testing/mocks/`, `testing/tests/`; results stay in `results/`. `source` in `widget.json` is now relative to the widget folder and defaults to `src` when that folder exists.
- The generated `playwright.config.ts` looks for tests in `widgets/**/testing/tests/` and stops the emulator with `SIGTERM`, so widgets started by `run` stop too.
- The agent instructions for widgets keep only facts about the emulator; the steps of testing a widget moved to the `widget-testing` skill.
- `bun run setup` builds the web app on Bun, so it no longer depends on the Node.js version.

### Removed

- `zoho-studio init` no longer copies the skill `zoho-crm-widget-testing` into new projects; the plugin's `widget-testing` skill replaces it.

## How to update

```bash
git pull
bun run setup
```

Then, in Claude Code, install the plugin from the clone and let it check the machine:

```bash
claude plugin marketplace add <path to the clone>
claude plugin install zoho-studio@zoho-studio
```

and run `/zoho-studio:setup` in a session.

In an existing project:

- **A script that writes to Zoho** — add `allowCrmWrites()` from `@zoho-studio/zoho-crm` before its first write; without it the script stops with `CRM_WRITES_DISABLED`.
- **Widgets** — in each `widgets/<name>/`, move `scenarios/` to `testing/scenarios/` and `tests/` to `testing/tests/`. In `playwright.config.ts` set `testMatch: '**/testing/tests/**/*.spec.ts'` and add `gracefulShutdown: { signal: 'SIGTERM', timeout: 5_000 }` to `webServer`. If `widget.json` has `source`, rewrite it relative to the widget folder, or drop it when the code moves into `src/`.
- **The old skill** — delete `.claude/skills/zoho-crm-widget-testing/` if the project has it.
- **Claude Code permissions** — copy `.claude/settings.json` from a new project made with `zoho-studio init`, if you want them.
