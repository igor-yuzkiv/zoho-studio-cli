# 0001. CLI встановлюється з клону репозиторію командою `bun run setup`

- **Статус:** Прийнято
- **Дата:** 2026-11-28

## Рішення

CLI встановлюється й оновлюється з локального клону репозиторію одним скриптом, `bun run setup`: він збирає виконуваний файл, створює посилання `~/.local/bin/zoho-studio` і реєструє пакети фреймворку через `bun link`. Підтримуються macOS і Linux; на Windows скрипт зупиняється з поясненням. `git pull` він ніколи не виконує: оновлення — це `git pull`, а потім `bun run setup`.

## Контекст

- Проєкти, створені `zoho-studio init`, імпортують пакети фреймворку (`@zoho-studio/core`, `auth`, `zoho-crm`) через реєстр посилань Bun, який указує на вихідний код клону. Тож клон на машині потрібен у будь-якому разі.
- Плагін Claude Code ставиться з того самого клону, тож його скіли й CLI беруться з одного місця й однієї версії.
- До цього рішення встановлення займало чотири ручні кроки, які люди й агенти повторювали вручну, а оновлення легко було зробити наполовину.
- Скіл `setup` плагіна має встановлювати й оновлювати CLI, а людина має могти зробити те саме без агента.

## Альтернативи

- **Готові виконувані файли для кожного релізу.** Відхилено поки що: скриптам проєктів однаково потрібні пакети з клону, а публікація бінарників потребує конвеєра збірки, якого в проєкті немає.
- **Глобальний npm-пакет.** Відхилено: пакети не мають кроку збірки й використовуються як вихідний код TypeScript через реєстр посилань; публікація додала б збірку й реєстр, які треба підтримувати.
- **Кроки в скілі `setup` замість скрипту.** Відхилено: скрипт ідемпотентний, тестується й працює без агента; скіл лише викликає його.
- **`setup` сам підтягує репозиторій.** Відхилено: скрипту довелося б вирішувати, що робити з локальними змінами чи іншою гілкою. Один скрипт — одна робота; підтягує людина або скіл.

## Наслідки

- Встановлення — `git clone` і `bun run setup`; оновлення — `git pull` і `bun run setup`. Повторний запуск безпечний.
- Посилання на інший клон або файл на його місці зупиняє скрипт; `--force` замінює його, `--bin-dir` ставить в іншу папку.
- Скрипт не змінює файли оболонки: якщо папки немає в `PATH`, він друкує рядок, який треба додати для оболонки користувача.
- Bun і git — передумови: скрипт перевіряє їх, користуючись ними, а не встановлює.

## Межі

Переглянути, коли CLI треба буде ставити без Bun або без клону — для користувачів, які не пишуть скриптів, або для Windows, — чи коли пакети отримають крок збірки й реєстр.
