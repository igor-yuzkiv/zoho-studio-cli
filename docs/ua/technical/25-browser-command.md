# `zoho-studio browser`

Відкриває проєкт у локальному вебзастосунку: артефакти в `src/` можна переглядати на сторінці, а будь-яку
їхню групу — завантажити з неї знову. Запускайте команду в папці проєкту.

```bash
zoho-studio browser               # free port, opens the default browser
zoho-studio browser --port 4321   # fixed port
zoho-studio browser --no-open     # start the server only
```

```text
Zoho Studio is running at http://127.0.0.1:41853/
Press Ctrl+C to stop.
```

Сервер слухає лише `127.0.0.1`. Він може запускати завантаження зі збереженими токенами проєкту, тому
ніколи не доступний з інших машин і відповідає лише власній сторінці: запит з іншого
сайту, відкритого в тому самому браузері, або запит, адресований іншому імені хоста, відхиляється. Сервер працює, доки ви не зупините його через Ctrl+C.

## Завантаження зі сторінки

Завантаження, запущене зі сторінки, виконує той самий код, що й відповідна команда `z-crm:*:pull`, з тими самими опціями й тими самими записаними файлами. Одночасно виконується лише одне
завантаження: завантаження спільно використовують папки проєкту та сховище токенів, тож друге відхиляється,
доки не завершиться перше. Сторінка показує перебіг, а наприкінці — той самий підсумок, що й
команда.

## Лог

Огляд завершується логом проєкту — файлом, у який пише кожна команда, `logs.file` у
[налаштуваннях](2-settings.md), — найновіший запис першим. Старіші записи довантажуються під час прокручування, а запис
розгортається, показуючи решту своїх полів.

## Вхід зі сторінки

Рядок стану показує, чи збережено в проєкті refresh token, і має кнопку, що відкриває
той самий вхід, що й [`zoho-studio login`](4-login-command.md). Діалог запитує, з яким профілем облікових даних
увійти. Останній пункт списку профілів створює новий
профіль з назви, client id та client secret перед початком входу.

Потім сторінка показує посилання для підтвердження та код, який треба ввести, чекає на схвалення і
зберігає токени в `~/.zoho-studio` так само, як це робить CLI. Client secret надходить на
сервер один раз, під час створення профілю, і ніколи не повертається на сторінку. Завантаження, що не вдалося,
бо в проєкті не виконано вхід, пропонує ту саму кнопку.

## Запуск із вихідного коду

Виконуваний файл із `bun run compile` містить сторінку в собі, тож `zoho-studio browser` працює
всюди, куди скопійовано файл. Коли CLI запускається з вихідного коду, сторінка віддається з `dist/web`,
тож спершу зберіть її:

```bash
bun run build:web
bun run dev -- browser
```

Під час роботи над самою сторінкою запускайте сервер із фіксованим портом, а поруч — dev-сервер Vite;
Vite перенаправляє `/api` на сервер:

```bash
bun run dev -- browser --port 4321 --no-open   # inside a project folder
bun run dev:web                                # in this repository
```

## HTTP API

Сторінка спілкується із сервером через JSON; `POST` має надсилати `Content-Type: application/json`. Шляхи відносні до `src/` проєкту; шлях, що
вийшов би за межі `src/`, відхиляється.

| Метод і шлях | Повертає |
|---|---|
| `GET /api/project` | назву й шляхи проєкту, збережену організацію, чи збережено refresh token |
| `GET /api/groups` | кожну групу артефактів з її командою завантаження, опціями, папкою, кількістю артефактів і часом найновішого файлу |
| `GET /api/tree?path=&depth=` | файли й папки під шляхом |
| `GET /api/file?path=` | один файл так, як він є на диску, завжди як звичайний текст |
| `GET /api/json?path=` | кожен файл JSON під шляхом, розібраний, з ключем за його шляхом |
| `GET /api/pulls` | останні завантаження, найновіші першими |
| `POST /api/pulls` | запускає завантаження: `{ "area": "crm", "group": "fields", "options": { "module": "Leads" } }`; `409`, поки виконується інше |
| `GET /api/logs?before=&limit=` | лог проєкту, найновіші першими, сторінка за сторінкою; `nextCursor` читає старішу сторінку |
| `GET /api/login` | стан входу, запущеного зі сторінки |
| `GET /api/profiles` | збережені профілі облікових даних, лише назва та client id |
| `POST /api/profiles` | створює профіль: `{ "name": "acme", "clientId": "…", "clientSecret": "…" }`; `409`, коли назву вже зайнято |
| `POST /api/login` | запускає вхід: `{ "profile": "acme" }`; `409`, поки інший чекає на схвалення |
| `GET /api/events` | потік server-sent events з кожною зміною завантаження чи входу |
