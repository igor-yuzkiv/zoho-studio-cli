# `zoho-studio z-crm:static-resources:pull`

Завантажує всі статичні ресурси Zoho CRM — файли JavaScript, які підключають клієнтські скрипти, — у
`src/zoho-crm/static-resources/`, по одній директорії на ресурс, з його метаданими та файлом.

```bash
zoho-studio z-crm:static-resources:pull
```

```text
Pulling static resources |████████████████████| 15/15 | pricingHelpers
Static resources found: 15
Metadata saved: 15
Files downloaded: 15
Files failed: 0
```

Команді потрібен проєкт, у якому виконано [`zoho-studio login`](4-login-command.md) з
дозволом `ZohoCRM.settings.static_resources.READ`, який є серед типових.

## Що потрапляє на диск

Файли записуються в корені проєкту — у папці, що містить `.zoho-studio/`, а не в поточній
директорії.

```text
src/zoho-crm/static-resources/
├── user/
│   └── pricingHelpers.1000000000053904403/
│       ├── pricingHelpers.metadata.json
│       └── pricingHelpers.js
├── crm/
│   └── ZDK-1.0.1000000000000476013/
│       └── …
└── internal/
    └── DotSDK-2.0.1000000000000476015/
        ├── DotSDK-2.0.metadata.json
        └── crm_dot_sdk.js.gzip
```

Завантажується кожен ресурс, який перелічує Zoho, а перший рівень розподіляє їх за `source`: `user` — для
файлів, завантажених у цій організації, `crm` та `internal` — для бібліотек, які постачає сама Zoho.
Директорія ресурсу називається за ресурсом і його id; файл у ній зберігає
`file_name`, який повідомляє Zoho.

`*.metadata.json` містить повний запис ресурсу точно в тому вигляді, в якому його повернула Zoho, з
відступом у чотири пробіли та кінцевим переходом на новий рядок. Файл — це той, що стоїть за `uri` ресурсу, записаний
байт у байт: gzip-ресурси Zoho лишаються gzip. `uri` розташований поза Zoho CRM і запитується
без токена OAuth, так само як його запитує веб-інтерфейс CRM.

**Цільова директорія видаляється й створюється заново під час кожного запуску.** Вона завжди відображає поточне завантаження,
тож ресурс, видалений у Zoho, зникає локально, а будь-яка локальна правка в ній втрачається.

## Збої

Ресурс, файл якого не вдається отримати, не зупиняє запуск: його метадані все одно записуються, файл
не створюється, а ресурс вказується в підсумку з коротким описом помилки. Невдача під час отримання самого переліку
ресурсів є фатальною, бо записувати було б нічого.

## Логи

CLI пише структуровані логи JSON у [`logs.file`](2-settings.md), за замовчуванням `logs/zoho-studio-cli.log`.
`z-crm:static-resources:pull` записує початок запуску, кількість знайдених ресурсів,
підсумкові лічильники та кожен збій зі стеком викликів. Токени й заголовки авторизації ніколи
не потрапляють у лог.
