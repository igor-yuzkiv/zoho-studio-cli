# `zoho-studio z-crm:webhooks:pull`

Завантажує кожен вебхук Zoho CRM у пласку папку `data/zoho-crm/webhooks/` — по одному JSON-файлу на вебхук,
разом із тілом запиту, заголовками, параметрами URL та автентифікацією, яких немає в самому списку
вебхуків.

```bash
zoho-studio z-crm:webhooks:pull
```

```text
Pulling webhooks |████████████████████| 30/30 | SRV.Programs.Delete
Webhooks found: 30
Webhooks saved: 30
Webhooks failed: 0
```

Команда потребує проєкту, який пройшов [`zoho-studio login`](4-login-command.md), з наданим
дозволом `ZohoCRM.settings.automation_actions.READ`. Без нього Zoho відповідає
`OAUTH_SCOPE_MISMATCH`; дозвіл є в типових [налаштуваннях](2-settings.md), тож проєкт,
створений до його додавання, треба авторизувати знову.

Вебхуки — це дії, які викликає [правило робочих процесів](9-workflows-pull-command.md). Та команда
записує їх лише як посилання — назва, id, тип, — тож саме ця кладе на диск їхній справжній
вміст. Жодна з команд не постачає даних іншій: вони звертаються до різних ендпоінтів і пишуть у різні папки.

Вебхуки отримуються по одному — запит списку, а потім по одному запиту на кожен вебхук за його повним
записом, — з короткою затримкою між ними, щоб не впертися в ліміти API Zoho. Індикатор прогресу показує
вебхук, який завантажується зараз.

## Що з'являється на диску

```text
data/zoho-crm/webhooks/
├── SRV.Programs.Delete.json
├── SRV.Shipping_Packages.Upsert.json
└── Notify Billing.json
```

Кожен файл містить повний запис вебхука таким, яким його повернув `GET /settings/automation/webhooks/{id}`,
відформатований з відступом у чотири пробіли й завершальним переведенням рядка. Цей запис містить `url`,
`http_method`, `body`, `headers`, `url_parameters` і `authentication` — частини, що описують,
що саме вебхук надсилає. Зверніть увагу: `authentication` називає підключення, яке використовує Zoho; жодного
секрету у відповіді немає.

Папка завжди `data/zoho-crm/webhooks/`; жодне налаштування її не переносить.

**Уся папка видаляється й створюється заново під час кожного запуску**, тож вебхук, видалений у Zoho, зникає
й локально, а будь-яка локальна правка втрачається.

Файли названо за вебхуком. Замінюються лише символи, яких не може бути в сегменті шляху;
більше нічого в назві не змінюється. Коли два вебхуки претендують на одне й те саме ім'я файлу, другий
отримує ще й свій id — `Notify Billing.6640142000024463018.json`. Вебхуки обробляються у
фіксованому порядку — за модулем, потім за назвою, потім за id, — тож запуск завжди називає їх однаково.

Команда завантажує всю організацію; опції `--module` немає.

## Які правила використовують вебхук

Не завантажується. Zoho повідомляє це окремо, через
`settings/automation/webhooks/{id}/actions/associations`, а ця команда його не викликає. Зворотний
напрямок доступний: файл правила з [`z-crm:workflows:pull`](9-workflows-pull-command.md)
перелічує вебхуки, які воно викликає.

## Збої

Вебхук, повний запис якого не вдається отримати, не зупиняє запуск: він потрапляє в підсумок
із коротким описом помилки, решта вебхуків усе одно завантажується, і команда все одно завершується успішно.

```text
Webhooks failed: 1
  - SRV.Programs.Delete: permission denied (OAUTH_SCOPE_MISMATCH)
```

Неможливість отримати *список* вебхуків фатальна — записувати нічого.

## Логи

CLI пише структуровані JSON-логи в [`logs.file`](2-settings.md), типово `logs/zoho-studio-cli.log`.
`z-crm:webhooks:pull` фіксує початок запуску, скільки вебхуків знайдено, підсумкові
кількості та кожен збій зі стеком викликів. Окремі успішні вебхуки не потрапляють у лог — їх уже показує
індикатор прогресу.
