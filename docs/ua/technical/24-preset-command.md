# `zoho-studio preset`

Виконує іменовану послідовність команд CLI, одну за одною, з розділу `presets` налаштувань
проєкту.

```bash
zoho-studio preset                        # list the presets
zoho-studio preset pull-crm               # run one
```

```text
[1/11] zoho-studio z-crm:org:info
…
[2/11] zoho-studio z-crm:modules:pull
…
Preset "pull-crm" finished: 11 steps
```

## Визначення пресетів

`presets` у [`.zoho-studio/settings.json`](2-settings.md) зіставляє назву пресета зі списком командних
рядків. Кожен рядок — це те, що ви набрали б після `zoho-studio`:

```json
{
    "presets": {
        "pull-leads": ["z-crm:modules:pull", "z-crm:fields:pull --module=Leads"]
    }
}
```

Аргументи розділяються пробілами; значення, що містить пробіли, беріть в одинарні або подвійні
лапки. Жоден інший синтаксис оболонки не розпізнається — ні змінні, ні конвеєри, ні `&&`.

Один пресет вбудований: `pull-crm` — `z-crm:org:info`, потім усі команди `z-crm:*:pull`, причому
`z-crm:modules:pull` іде перед `z-crm:fields:pull` і `z-crm:layouts:pull`, як того вимагають ці завантаження.

Пресети об'єднуються з вбудованими за назвою: пресет, який ви визначили, додається, а пресет із
назвою вбудованого повністю його замінює.

## Як виконується пресет

Перед першим кроком перевіряється кожен рядок: рядок, що не називає жодної команди `zoho-studio` або
викликає сам `preset`, зупиняє запуск, нічого не виконавши. Пресети не можуть викликати інші пресети.

Потім кроки виконуються по черзі в тому самому процесі. Крок, що завершився помилкою, зупиняє пресет, а помилка
називає цей крок. Крок, що завершився частковим збоєм, про який він лише повідомляє, — наприклад, пропущеною сутністю, —
не зупиняє пресет, але запуск однаково завершується ненульовим кодом виходу.

Невідома назва пресета дає помилку зі списком доступних пресетів.
