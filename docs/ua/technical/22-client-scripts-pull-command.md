# `zoho-studio z-crm:client-scripts:pull`

Завантажує всі клієнтські скрипти Zoho CRM проєкту в `data/zoho-crm/client-scripts/` — по одній
директорії на скрипт, з його метаданими та кодом JavaScript.

```bash
zoho-studio z-crm:client-scripts:pull
```

```text
Pulling client script pages |████████████████████| 39/39 | _no-module/commands
Pages found: 39
Scripts found: 61
Source downloaded: 60
Failed: 1
  - Deals/module_edit.Standard/Validate Amount (1000000000002968001): Request failed with status code 404
```

Команді потрібен проєкт, у якому виконано [`zoho-studio login`](4-login-command.md). Вона
читає з дозволом `ZohoCRM.settings.client_scripts.READ`, який є серед типових.

## Що потрапляє на диск

Файли записуються в корені проєкту — у папці, що містить `.zoho-studio/`, а не в поточній
директорії.

```text
data/zoho-crm/client-scripts/
├── Deals/
│   ├── module_create.Retail/
│   │   ├── page.metadata.json
│   │   ├── Filter Contacts By Layout.1000000000000521219/
│   │   │   ├── Filter Contacts By Layout.metadata.json
│   │   │   └── Filter Contacts By Layout.js
│   │   └── Set Default Owner.1000000000001000061/
│   │       └── …
│   └── module_view_canvas.Standard.Retail Overview/
│       └── …
└── _no-module/
    └── commands/
        └── …
```

Клієнтські скрипти в Zoho належать сторінці: екрану модуля (`module_create`, `module_edit`,
`module_clone`, `module_detail`, `module_view_canvas`) одного макета або сторінці `commands`, що
не належить жодному модулю. Дерево повторює це:

- **Директорія модуля** — відображувана назва модуля, як її показує інтерфейс CRM; сторінка без
  модуля потрапляє в `_no-module/`.
- **Директорія сторінки** — визначення сторінки, потім API-назва макета та назва canvas, якщо
  вони є в сторінки. Якщо дві сторінки модуля отримують однакову назву, до пізнішої за id
  додається її id. `page.metadata.json` містить запис сторінки точно в тому вигляді, в якому його повернула Zoho.
- **Директорія скрипта** — назва скрипта та його id. Id є завжди, бо Zoho дозволяє
  два скрипти з однаковою назвою на одній сторінці.

`*.metadata.json` містить повний запис скрипта точно в тому вигляді, в якому його повернув ендпоінт переліку, — подію,
стан, пріоритет, авторів і дати — з відступом у чотири пробіли та кінцевим переходом на новий рядок.
`*.js` містить код так, як його написав автор, без форматування й розбору. У назвах замінюються лише символи,
яких не може містити сегмент шляху.

Код читається з hosting url скрипта — файлу, який завантажує веб-інтерфейс CRM, — а не з
ендпоінта налаштувань `/code`, що віддає транспільовану форму скрипта. Hosting url розташований
поза Zoho CRM і запитується без токена OAuth, так само як його запитує веб-інтерфейс.

Zoho не надає попередніх ревізій скрипта, тож завантаження містить лише поточну версію. Закомітьте
завантажене дерево, щоб зберігати історію.

**Цільова директорія видаляється й створюється заново під час кожного запуску.** Вона завжди відображає поточне завантаження,
тож скрипт, видалений у Zoho, зникає локально, а будь-яка локальна правка в ній втрачається.

## Збої

Сторінка, скрипти якої не вдається отримати, або скрипт, код якого не вдається завантажити, не зупиняє
запуск: усе, що можна записати, записується, а збій вказується в підсумку з коротким
описом помилки. Команда все одно завершується успішно.

Невдача під час отримання самого переліку сторінок є фатальною, бо записувати було б нічого.

Сторінки запитуються по одній з короткою затримкою між ними, щоб не впертися в ліміти API
Zoho.

## Логи

CLI пише структуровані логи JSON у [`logs.file`](2-settings.md), за замовчуванням `logs/zoho-studio-cli.log`.
`z-crm:client-scripts:pull` записує початок запуску, кількість знайдених сторінок,
підсумкові лічильники та кожен збій зі стеком викликів. Токени й заголовки авторизації ніколи не
потрапляють у лог.
