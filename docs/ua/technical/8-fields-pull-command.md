# `zoho-studio z-crm:fields:pull`

Завантажує поля кожного локально збереженого модуля в підпапку `fields/` цього модуля — по одному
JSON-файлу на поле.

```bash
zoho-studio z-crm:fields:pull
```

```text
Pulling fields |████████████████████| 42/42 | Vendors
Modules processed: 42
Fields saved: 913
Modules failed: 1
  - Ghost_Module: Request failed with status code 400
```

**Спершу запустіть [`zoho-studio z-crm:modules:pull`](7-modules-pull-command.md) і повторюйте цю команду після
кожного `z-crm:modules:pull`.** Список модулів для обходу береться з локальної папки модулів, а не з
API, а `z-crm:modules:pull` видаляє й створює цю папку заново — і це знищує раніше завантажені поля.
Правильний порядок завжди `z-crm:modules:pull` → `z-crm:fields:pull`.

Команда також потребує проєкту, який пройшов [`zoho-studio login`](4-login-command.md),
з наданим дозволом `ZohoCRM.settings.fields.READ`.

## Що з'являється на диску

```text
data/zoho-crm/modules/
└── Leads/
    ├── Leads.metadata.json
    └── fields/
        ├── Last_Name.json
        ├── Email.json
        └── Custom_Field_1.json
```

Кожен файл названо за API-назвою поля, і він містить повний запис поля саме таким, яким його повернув
`GET /settings/fields`, відформатований з відступом у чотири пробіли й завершальним переведенням рядка. Замінюються лише
символи, яких не може бути в сегменті шляху; більше нічого в назві не змінюється.

Папка `fields/` фіксована — її не можна налаштувати. Її батьківська папка —
`data/zoho-crm/modules/`, та сама, в яку пише `z-crm:modules:pull`.

**Папка `fields/` кожного завантаженого модуля видаляється й створюється заново під час кожного запуску**, тож поле,
видалене в Zoho, зникає й локально, а будь-яка локальна правка в ній втрачається. Більше нічого не зачіпається:
файл метаданих модуля лишається на місці, а модуль, що не входить у запуск, зберігає свої
поля.

## Один модуль за раз

`--module` звужує запуск до одного модуля — це швидкий спосіб оновити один модуль, не
обходячи всю організацію:

```bash
zoho-studio z-crm:fields:pull --module=Leads
```

Значення — API-назва модуля, тобто назва його локальної папки. Значення, яке не є простою
назвою папки, або модуль без локальної папки зупиняють команду ще до того, як щось буде
видалено.

## Збої

Модуль, поля якого не вдається отримати, — немає підписки, його більше немає в Zoho, випадкова папка,
яка не є модулем, — не зупиняє запуск. Його наявна папка `fields/` лишається недоторканою,
модуль потрапляє в підсумок із коротким описом помилки, а решта модулів усе одно завантажується.
Команда все одно завершується успішно.

Запуск із порожньою чи відсутньою папкою модулів фатальний: обходити нічого, а помилка
вказує на `z-crm:modules:pull`.

Модулі запитуються по одному з короткою затримкою між ними, щоб не впертися в ліміти API Zoho,
тож організація з багатьма модулями обробляється якийсь час. Індикатор прогресу показує модуль,
який завантажується зараз.

## Логи

CLI пише структуровані JSON-логи в [`logs.file`](2-settings.md), типово `logs/zoho-studio-cli.log`.
`z-crm:fields:pull` фіксує початок запуску, скільки локальних модулів знайдено, підсумкові
кількості та кожен збій зі стеком викликів. Окремі успішні модулі не потрапляють у лог — їх
уже показує індикатор прогресу.
