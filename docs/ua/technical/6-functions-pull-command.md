# `zoho-studio z-crm:functions:pull`

Завантажує всі функції Zoho CRM проєкту в `data/zoho-crm/functions/` — по одній директорії на
функцію, з її метаданими та кодом Deluge.

```bash
zoho-studio z-crm:functions:pull
```

```text
Pulling functions |████████████████████| 77/77 | wf_leads_generatePublicLink
Functions found: 77
Metadata saved: 77
Code downloaded: 76
Code failed: 1
  - Send Invoice (send_invoice): Request failed with status code 500
```

Команда потребує проєкту, який пройшов [`zoho-studio login`](4-login-command.md).

## Що потрапляє на диск

Файли записуються відносно кореня проєкту — папки, що містить `.zoho-studio/`, а не поточної
директорії.

```text
data/zoho-crm/functions/
└── calculate_invoice_total/
    ├── Calculate Invoice Total.metadata.json
    └── Calculate Invoice Total.deluge
```

Директорію названо за API-назвою функції, файли — за її відображуваною назвою. Замінюються лише
символи, яких не може містити сегмент шляху; більше нічого в назві не змінюється.

`*.metadata.json` містить повний запис функції саме таким, яким його повернув ендпоінт списку,
відформатований з відступом у чотири пробіли та кінцевим переходом на новий рядок. `*.deluge`
містить код дослівно — його ніколи не форматують, не переносять і не розбирають.

**Цільова директорія видаляється й створюється заново під час кожного запуску.** Вона завжди
відображає поточне завантаження, тож функція, видалена в Zoho, зникає й локально, а будь-яка
локальна правка всередині неї втрачається.

Розташування фіксоване: `data/zoho-crm/functions/` у корені проєкту, створюється, якщо її немає.
Жодне налаштування його не змінює — дерево проєкту див. у [`zoho-studio init`](3-init-command.md).

## Збої

Функція, код якої не вдається отримати, не зупиняє запуск: її метадані все одно записуються,
файл коду не створюється, а сама функція потрапляє в підсумок із коротким описом помилки. Команда
все одно завершується успішно — часткові збої коду повідомляються, але не є фатальними.

Збій отримання самого списку функцій фатальний, бо тоді не було б чого записувати.

Запити коду виконуються по одному з короткою затримкою між ними, щоб не впертися в ліміти API
Zoho, тож великий проєкт завантажується не одразу.

## Логи

CLI записує структуровані JSON-логи в [`logs.file`](2-settings.md), типово
`logs/zoho-studio-cli.log`; файл створюється з першим записаним рядком — команда, яка нічого не
логує, не залишає файлу. `z-crm:functions:pull` записує початок запуску, кількість знайдених
функцій, підсумкові лічильники та кожен збій зі стеком викликів. Окремі успішні функції не
логуються — їх і так показує індикатор прогресу.

У терміналі залишаються індикатор прогресу, підсумок і короткі повідомлення про помилки; подробиці
лишаються у файлі логу. Токени й заголовки авторизації ніколи не логуються.
