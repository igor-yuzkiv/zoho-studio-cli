# `zoho-studio z-crm:functions:run`

Запускає код функції в Zoho й друкує відповідь Zoho. Код береться з локального джерела в `src/` або
зі знімка останнього pull у `data/`, надсилається як є й не зберігається: функція в Zoho лишається в
задеплоєній версії. Це те саме, що робить кнопка Run у редакторі Deluge в Zoho.

**Зміна в `src/` виконується ще до deploy.** Zoho виконує код, який надсилає команда, а не збережену
версію, тож функцію можна змінити локально, запустити, прочитати її логи й задеплоїти лише тоді,
коли вона робить те, що треба.

**Функція виконується по-справжньому.** Усе, що вона робить, — змінює записи, надсилає листи,
викликає вебхуки — відбувається в організації, до якої підключено проєкт. Спершу запускайте функції
на sandbox.

```bash
zoho-studio z-crm:functions:run                                    # вибрати джерело й функцію, відповісти про аргументи
zoho-studio z-crm:functions:run btn_send_quote --from src --arg id=1123 --arg count=2
zoho-studio z-crm:functions:run wf_sync --from data --dry-run      # надрукувати команду, нічого не надсилати
zoho-studio z-crm:functions:run btn_send_quote --from src -a id=1123 -a count=2 --force
```

## Опції

- `--from <src|data>` — звідки береться код: `src` — локальне джерело в `src/zoho-crm/functions/`,
  `data` — те, що було в Zoho на час останнього pull, у `data/zoho-crm/functions/`. Нічого не
  припускається: без опції команда питає, а без термінала зупиняється.
- `[api_name]` — папка функції в цьому місці. Без нього функцію вибирають зі списку функцій там;
  кілька літер звужують список.
- `-a, --arg <name=value>` — один аргумент функції; повторіть для кожного. Усе після першого `=` —
  значення. Ім'я, якого немає в оголошенні, відхиляється.
- `--dry-run` — друкує команду, яка запускає функцію з цими аргументами, і нічого не надсилає.
- `-f, --force` — запускає без запиту підтвердження.

## Аргументи

Аргументи беруться з оголошення функції — `string button.btn_send_quote(String id, Int count)`
питає `id` і `count`. Кожен, не переданий через `--arg`, команда питає в порядку оголошення:

```text
✔ Take the code from src/ — the local source
✔ Function to run btn_send_quote
✔ id (String) 1123
✔ count (Int) 2
```

Значення надсилаються як текст — так їх надсилає редактор Zoho.

`--dry-run` дає змогу перейти від запитань до команди, яку можна повторювати: дайте відповіді один
раз, і замість запуску функції команда надрукує повний виклик.

```text
zoho-studio z-crm:functions:run btn_send_quote --from src --arg id=1123 --arg count=2
```

## Підтвердження

Перед надсиланням команда каже, що станеться, і питає; за замовчуванням відповідь — ні.

```text
sa_ping will run in Zoho CRM with the code from src/.
Whatever it does happens for real: records it changes, emails it sends, webhooks it calls.
✔ Run the function? No
Nothing run.
```

`--force` пропускає запитання. Без термінала команда не може запитати, тож їй потрібні `--from`,
API-ім'я, усі аргументи через `--arg` і `--force`; інакше вона завершується з помилкою, що називає, чого
бракує.

## Результат

Відповідь Zoho друкується як відформатований JSON: статус, повернене значення з його типом, запис
логу для кожного `info` з номером рядка та метрики — кількість виконаних інструкцій, витрачений час
тощо. Код виходу — 1, якщо статус не `success`. Функцію, що не компілюється, команда показує з рядком
і позицією кожної помилки, як і deploy.

Zoho не документує endpoint, який використовує команда.
