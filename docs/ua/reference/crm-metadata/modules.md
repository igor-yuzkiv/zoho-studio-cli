# `zoho-studio z-crm:modules:pull`

Завантажує метадані кожного модуля Zoho CRM організації в `data/zoho-crm/modules/` — по одній
папці на модуль, у якій лежить його файл метаданих.

```bash
zoho-studio z-crm:modules:pull
```

```text
Pulling modules |████████████████████| 42/42 | Vendors
Modules found: 42
Metadata saved: 42
```

Команда потребує проєкту, який пройшов [`zoho-studio login`](../project/login.md), з наданим
дозволом `ZohoCRM.settings.modules.READ`.

## Що з'являється на диску

Файли записуються відносно кореня проєкту — папки, що містить `.zoho-studio/`, а не поточної
папки.

```text
data/zoho-crm/modules/
├── Leads/
│   └── Leads.metadata.json
└── CustomModule1/
    └── CustomModule1.metadata.json
```

І папка, і файл названі за API-назвою модуля, а не за його відображуваною назвою. API-назва стабільна
й унікальна і не змінюється, коли відображувану назву перейменовують у Zoho. Замінюються лише
символи, яких не може бути в сегменті шляху; більше нічого в назві не змінюється.

`*.metadata.json` містить повний запис модуля саме таким, яким його повернув ендпоінт, відформатований
з відступом у чотири пробіли й завершальним переведенням рядка.

**Ця команда відповідає лише за файл метаданих кожного модуля.** Поля, які [`zoho-studio z-crm:fields:pull`](fields.md) записує в `<module>/fields/`, і layouts, які [`zoho-studio z-crm:layouts:pull`](layouts.md) записує в `<module>/layouts/`, лишаються на місці. Файл метаданих, вміст якого не змінився, лишається як є, а змінений перезаписується.

Модуль, видалений у Zoho, переїжджає в `data/.removed/<дата-час>/` разом з усією папкою — метаданими, полями й layouts, — див. [Завантаження](../../guides/pulling.md). Спершу запускайте `z-crm:modules:pull`, а `z-crm:fields:pull` і `z-crm:layouts:pull` — після: вони проходять модулі з локальної папки.

Розташування фіксоване: `data/zoho-crm/modules/` у корені проєкту; якщо папки немає, її буде створено.
Жодне налаштування його не змінює — дерево проєкту див. у [`zoho-studio init`](../project/init.md).

## Збої

Уся команда — це один запит, тож неможливість отримати список модулів фатальна — записувати було б
нічого, а наявна папка лишається недоторканою, бо нічого не переноситься, доки список не надійшов.

## Логи

CLI пише структуровані JSON-логи в [`logs.file`](../project/settings.md), типово `logs/zoho-studio-cli.log`,
який створюється під час запису першого рядка. `z-crm:modules:pull` фіксує початок запуску, скільки
модулів знайдено, і підсумкову кількість. Токени й заголовки авторизації ніколи не потрапляють у логи.
