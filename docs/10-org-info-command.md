# `zoho-studio org:info`

Reads the organization the project is connected to, prints the fields worth seeing in a terminal,
and stores the full record in `.zoho-studio/org.json`.

```bash
zoho-studio org:info          # the readable card, plus the stored file
zoho-studio org:info --json   # the org record exactly as Zoho returned it
```

```text
Organization: Acme Inc
  id: 7000000012345
  type: sandbox
  domain: acme
  primary email: owner@acme.test
  location: Statesville, NC, US
  currency: US Dollar - USD
  time zone: EST
  created: 2025-07-22T10:28:51+03:00
  licence: zohooneenterprise, 20 users

Saved to /projects/acme/.zoho-studio/org.json
```

A field Zoho left empty is left out of the card; the stored file always holds the record whole,
which is why the two are not the same view. The file is rewritten on every successful run and is
not touched when the request fails, so a failed run keeps the previous snapshot.

The snapshot lives next to `settings.json` rather than under `src/`, because it describes the
project's connection rather than a resource pulled from Zoho. The `.gitignore` that
[`init`](3-init-command.md) puts in `.zoho-studio/` keeps it out of git — it is a local snapshot,
regenerated by any run of the command.

[`zoho-studio login`](4-login-command.md) runs the same pull once the tokens are stored, so a fresh
project has the file without a second command. A failure there is only reported — the login itself
still succeeds.

`org:info` needs a project that has been through `zoho-studio login`. Where
[`status`](5-status-command.md) is the short connectivity check, `org:info` is the full record and
the file that comes with it.
